## Step 1 — Research (top 3)

### R1. Contextual prefixes on sidecar / sub-atom chunks

- **Approach:** At ingest, prepend a 50–100 token “where this chunk sits in the parent atom” string before embedding and BM25 — Anthropic Contextual Embeddings + Contextual BM25. Apply only where EP already splits (RFC-004 sidecars, EP MCP `##`/`###` sub-chunks). Do not add standalone summary files. Anthropic’s own ablations found generic document summaries and summary-based indexing performed poorly.
- **Source:** Anthropic — [Contextual Retrieval in AI Systems](https://www.anthropic.com/engineering/contextual-retrieval) (2024-09-19; still cited as the 2026 practice). Cookbook: [contextual-embeddings/guide.ipynb](https://github.com/anthropics/claude-cookbooks/blob/main/capabilities/contextual-embeddings/guide.ipynb).
- **EP mapping:** `ep-chunk-annotate.py` / ingest-gate / EP MCP index path; optional field on sidecar rows or AKS `canonical_statement` for sub-chunks. Opening paragraphs already do this job for whole atoms.
- **Metric:** retrieval failure rate / hit rate on sidecar-backed and FAQ-H3 queries (blender-3d or a sidecar-heavy process pack); compare to current hybrid+MMR baseline in `guides/consumption.md`.
- **Risk:** LLM-generated prefixes can hallucinate parent context or become a stealth aggregator. Cost at ingest. Must not be written into the canonical Markdown body (deploy-prep already strips frontmatter; prefixes should stay index-side).
- **Next action:** consider
- **Decision:** apply
- **Notes:** Applied as deterministic sidecar field (no LLM). Stacks with hybrid search EP already recommends. Reranking was a further −67% failure in Anthropic’s test; treat rerank as a separate consumption-guide experiment. EP MCP must prepend the prefix at index time.

### R2. Hierarchical retrieval interfaces (search, then read the atom)

- **Approach:** Expose retrieval as tools at multiple granularities — keyword search, semantic search, then `chunk_read` / `memory_get` of the whole atom — so the agent incrementally gathers evidence instead of stuffing top-k fragments. A-RAG reports better QA at comparable or lower retrieved tokens. Pair with a tight step budget (3–7) and a stop condition so the loop cannot run away.
- **Source:** A-RAG — [Scaling Agentic RAG via Hierarchical Retrieval Interfaces](https://arxiv.org/pdf/2602.03442) (2026-02). Industry pattern survey: [Agentic RAG Patterns 2026](https://www.digitalapplied.com/blog/agentic-rag-patterns-multi-step-reasoning-guide).
- **EP mapping:** EP MCP already has search + get + `ep_graph_traverse`. Missing is a documented, eval’d consume path: “search → read whole atom → optional `requires:` expand → stop,” plus query-complexity gating (single-shot vs iterative). This is the existing ROADMAP “Agentic RAG / two-pass retrieve→focus” item with a concrete interface.
- **Metric:** tokens/query and correctness on the blender-3d eval set vs current top-k chunk dump; also TAC claim coverage if reconstruct is on.
- **Risk:** Unbounded agentic loops (latency/cost). Adaptive skip-retrieval for GK questions could hide EK the model thinks it knows.
- **Next action:** pilot
- **Decision:** apply
- **Notes:** Applied as the consume contract in `guides/consumption.md`. Complements R1. Do not turn this into a second memory product (Letta/MemGPT paging is episodic; EP stays curated expertise). Runtime tool loop is still ep-mcp.

### R3. Knowledge Activation — atoms as action-ready skill units

- **Approach:** Treat high-value workflow / decision / gotcha atoms as Agent-Skill-shaped units: what to do, which tools, constraints, and where to go next — loaded by progressive disclosure (metadata → body → references) rather than retrieved as undifferentiated text. Institutional-knowledge paper argues RAG fragments fail operational tasks; Agent Skills (Dec 2025 standard) are the portable primitive.
- **Source:** [Knowledge Activation: AI Skills as the Institutional Knowledge Primitive](https://arxiv.org/html/2603.14805v2) (2026-03). Loading model: [Claude Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview.md).
- **EP mapping:** EP already maps `type: workflow` + `retrieval_strategy: atomic` to MCP Prompts. Extend the contract so workflow/decision/gotcha atoms declare an optional `activation:` block (tools, constraints, next atom) and so pack skills / MCP registration use the same three-level load as Agent Skills. Do not fork a parallel `skills/` tree inside every pack.
- **Metric:** workflow-category correctness and tokens/query on process + product eval sets; skill-trigger precision (wrong workflow loaded = fail).
- **Risk:** Skill-metadata bloat in Tier 1. Turning every concept into a skill destroys retrieval-first packs (axiom 13). Keep this to operational atoms.
- **Next action:** consider
- **Decision:** apply
- **Notes:** Applied as optional `activation:` frontmatter. Progressive disclosure for *framework* schema projections was standing work (step 3). This item is pack-content activation.
