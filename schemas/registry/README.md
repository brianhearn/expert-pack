# ExpertPack Registry Schemas

Descriptive machine-readable projections of ExpertPack Markdown atoms.

Markdown remains canonical. Registry records are deterministic export artifacts for systems that need compact retrieval rows, graph/triple stores, exact ID lookups, validation, or interop with non-Markdown pipelines.

## Agent Knowledge Schema (AKS)

`agent-knowledge.spec.yaml` is a descriptive YAML spec for the compact provenance-first row emitted by:

```bash
python tools/micro-record-exporter/ep-micro-record-export.py \
  --pack path/to/pack \
  --compact \
  --output exports/pack.aks.jsonl
```

AKS is intentionally small. It carries only the fields an agent retrieval pipeline needs to ground an answer and verify the source:

- `schema`
- `id`
- `canonical_statement`
- `title`
- `type`
- `pack`
- `canonical_path`
- `source_span_uri`
- `content_hash`
- `source_checksum`
- optional `verified_at`, `verified_by`, `recorded_at`, `valid_from`
- optional graph fields: `requires`, `related`, `supersedes`

Use AKS when token efficiency, deterministic citations, or easy ingestion into a retrieval/indexing system matters more than preserving the full JSON-LD envelope.

## Full Micro-Records

The default exporter output remains the richer micro-record shape with JSON-LD context, nested `provenance`, lifecycle metadata, tags, and edges. Use full micro-records for archival interchange, richer graph loading, or systems that want the complete record envelope.

## Accepted Ontology

`ontology.spec.yaml` is a descriptive YAML spec for `ontology.yaml`, the maintainer-approved ontology registry for a pack. Suggestions generated by `ep-ontology-suggest.py` are not authoritative until accepted into this file. `ep-graph-export.py` consumes accepted entries from `ontology.yaml` and ignores raw suggestions.

## Content-File Frontmatter Contract

`frontmatter.spec.yaml` is the descriptive spec for the per-file YAML frontmatter enforced by `ep-validate --strict`. Its companion `frontmatter.schema.json` is a standards-based JSON Schema (draft 2020-12) so external tools can validate the same contract the CLI gate enforces — parse a file's frontmatter block to an object and validate it against the schema. The required set is `title`, `type`, `tags`, `pack`, `id`, `schema_version`, `retrieval_strategy`, `verified_at`, and `content_hash`.

## Chunk Metadata Sidecar

`chunk-sidecar.spec.yaml` describes the `<name>.chunks.yaml` sidecar generated by `tools/chunker/ep-chunk-annotate.py` (see [RFC-004](../rfcs/RFC-004-chunk-metadata-sidecars.md)). It records header-aware chunk boundaries — `chunk_id`, `chunk_order`, `line_range`, `tokenizer_tokens`, `chunk_summary` — beside an oversized file so the indexer can split and reassemble it deterministically without embedding chunk metadata into the body. The validator enforces `W-CHUNK-01..03`.

## Typed Answer Contract (TAC)

`typed-answer.spec.yaml` describes the response envelope an agent emits when answers must be auditable, and `typed-answer.schema.json` is its JSON Schema (draft 2020-12). TAC is the response layer on top of the Fragment Provenance retrieval layer (see [RFC-003](../rfcs/RFC-003-fragment-provenance-reconstruct-mode.md)): every claim maps to one or more retrieved source fragments, each graded `supported`, `partial`, or `unsupported`. In `reconstruct` mode each source must carry a `fragment_id`. Validate envelopes structurally with `tools/tac/validate_tac.py` and score them in evals with `tools/eval-runner/claim_verifier.py --tac`. The agent prompt contract lives in `templates/TAC-PROMPT.md`.

## Spec Format

The `.spec.yaml` files are ExpertPack-native descriptive specs, not JSON Schema 2020-12 or OpenAPI documents. They are intended for humans, agents, exporters, and custom validators. Where strict standards-based validation is required, a companion `.schema.json` is provided (see `frontmatter.schema.json`) rather than overloading the descriptive specs.

## Rule of Thumb

- **Authoring:** Markdown files
- **Agent retrieval / compact pipelines:** AKS JSONL (`--compact`)
- **Graph/registry interchange:** full micro-record JSONL
- **Runtime verification:** EP MCP reconstruct mode
